## 一、评价维度（九维，可扩展）

本标准采用**九维评价体系**，由 5个定量维度 + 4个定性维度 构成。维度表为**可扩展结构**——后续如需增加检查维度（如"节奏""爽点密度""逻辑自洽"），只需在引擎 `DIMENSIONS` 配置中追加一条，引擎自动纳入评测，无需修改任何代码逻辑。

| # | 维度 | 类型 | 检测口径 | 方向 |
|---|------|------|----------|------|
| 1 | 钩子强度 | 定量 | 前500字内钩子词表命中数 | 越大越好 |
| 2 | 对话密度 | 定量 | 全文引号对数 / 千字 | 越大越好 |
| 3 | 目标清晰度 | 定量 | 前3000字内目标词表命中数 | 越大越好 |
| 4 | 金手指速度 | 定量 | 第一章前3500字内金手指信号首次出现位置（字偏移） | **越小越好** |
| 5 | 幽默调节 | 定量 | 前4000字内幽默词表命中数 | 越大越好 |
| 6 | 文笔 | 定性 | 人工/模型评定（语言质感、节奏、画面感） | 越大越好 |
| 7 | 代入感 | 定性 | 人工/模型评定（主角视角锁定、情感共鸣） | 越大越好 |
| 8 | 情感厚度 | 定性 | 人工/模型评定（亲情/牺牲/守护等情感浓度） | 越大越好 |
| 9 | 职业爽点 | 定性 | 人工/模型评定（专业判断兑现、打脸破局密度） | 越大越好 |

## 二、评分方法

### 2.1 定量维度评分（百分位 + 凝练提纯区）

每个定量维度，将稿件值映射到**37本对标样本分布**的百分位，换算为15分制：

```
维度分 = 分位分(0~10) + 凝练提纯分(0~5)
```

- **分位分（0~10分）**：稿件值在样本中的百分位 × 10。方向为"越大越好"的维度百分位越高分越高；金手指速度（越小越好）百分位**反向**——位置越靠前分越高。未检测到金手指信号（前3500字无）按 2.0 分处理。
- **凝练提纯分（0~5分）**：当稿件值**超过样本最大值**时，按超出比例给分：
  ```
  凝练提纯分 = min(5, 超出比例 × 5)    超出比例 = (稿件值 - 样本最大值) / 样本最大值
  ```
  达到或超过样本最大值 = 满分 15 分（10 + 5）。
- **维度满分 = 15分 = 10分(行业顶级) + 5分(凝练提纯区)**。

### 2.2 定性维度评分

由人工/模型按 **15分制**评定。默认基准（10分制值 × 1.5）：文笔14.25、代入感13.5、情感厚度13.5、职业爽点13.8，**每轮评测自动叠加 ±0.45 随机波动**，模拟多位评委视角差异，避免单次评分定生死。

### 2.3 动态权重

每轮评测权重不同，保证"评测不少于11遍"不是简单重复：

- **定量维度**：熵权法（信息熵越小权重越大）× 0.5 + 变异系数法（区分度越大权重越大）× 0.5，再叠加 ±0.02 随机扰动。
- **定性维度**：从权重池（0.10~0.18）中随机抽取。
- 全部权重**归一化**后加权求和。

## 三、评测流程（≥11轮，双层去极值）

### 3.1 执行要求

1. 每个章节评测**不少于11轮**（引擎默认11轮，可指定更多）。
2. 每轮使用**不同的动态权重**与**不同的定性评分波动**（引擎按seed自动生成）。
3. 每轮计算：
   - **加权总分** = Σ(维度分 × 该轮权重)
   - **稳健总分** = 9维得分**去掉最高分和最低分**后，剩余7维的平均分

### 3.2 达标判定（150%）

**150%口径（2026-08-31主理人裁定）**：

```
150% = 满分10分 × 1.5 = 15分
```

含义：作者写到 **10分（行业顶级）还不够**，要在10分之上**再提高5分**（凝练提纯区 10~15分）——"凝练，提纯"，超越行业顶级50%才算合格。评分量纲为15分制。

双层统计，两层都要过：

1. **第一层（每轮去极值）**：每轮9维去最高最低后平均（稳健总分）≥ 15。
2. **第二层（轮次去极值）**：全部轮次的稳健总分，**再去掉一个最高、一个最低**，剩余轮次取平均 ≥ 15。
3. **二次统计**：全部轮次稳健总分的总平均（含极值轮次）也 ≥ 15，作为附加确认。

**判定结论**：三层全部达标 → 章节合格；任一层不达标 → 不合格，需修改后重评。

### 3.3 评测报告

每次评测输出 JSON 报告（含每轮9维得分、权重、稳健总分、双层统计、判定结论），存于 `对标样本\vXX_九维评测_N轮.json`，作为章节交付附件。

## 四、结果解读与迭代

| 稳健总分 | 评级 | 处置 |
|----------|------|------|
| ≥ 15.0 | 优秀（150%达标） | 可交付，可作投稿/爆款储备 |
| 13.0 ~ 15.0 | 良好（行业顶级以上） | 可交付，接近凝练提纯 |
| 10.0 ~ 13.0 | 达标（行业顶级） | 可交付，需继续凝练提纯 |
| 8.5 ~ 10.0 | 临界 | 需优化（优先补低于10的维度） |
| < 8.5 | 不合格 | 返工重写 |

**迭代指引**（15分制下，重点在"凝练提纯"）：
- 钩子/金手指 <10 → 重写开局，事件/对话驱动，金手指前置；>10 → 进一步前置、加强钩子密度。
- 对话密度 <10 → 增加对白、减少静态叙述；>10 → 对话信息量提纯（每句对白同时推进人设+剧情）。
- 代入感/文笔 13~15 → 向"一句顶三句"的凝练文风打磨。
- 职业爽点 <10 → 增加专业判断兑现场景；>10 → 提高打脸密度与专业纵深。

## 五、维度扩展指南（预留余地）

需要新增检查维度时（如第10维"节奏把控"），按以下步骤：

1. 在引擎 `DIMENSIONS` 列表中追加一条：
   ```python
   {"id": "pace", "name": "节奏把控", "type": "quant", "source": "事件密度(事件数/千字)", "direction": 1, "window": "全文"},
   ```
   - `type="quant"` 需在 `calc_features()` 中同步实现该特征提取；
   - `type="qual"` 则自动按定性维度处理（需在权重池 `QUAL_WEIGHT_POOL` 中配置）。
2. 若为定量维度，需同步在 `对标样本\特征数据_全量.json` 的样本数据中补充该特征列（用于分布基准）。
3. 引擎自动纳入加权与去极值统计，**无需改评测逻辑**。
4. 更新本标准文档的维度表。
